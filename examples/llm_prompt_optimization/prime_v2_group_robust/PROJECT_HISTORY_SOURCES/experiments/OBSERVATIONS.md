# Observations & lessons (GRAPE / PRIME E0+)

Living log of mistakes, metric traps, and confirmed facts. **Read before changing E0/E1 protocol.**

---

## Metric & evaluation

| ID | Observation | Do / Don't |
|----|-------------|------------|
| M1 | Snapshot Spearman(user_acc, cluster_acc) **includes the user in cluster_acc** → mechanical self-correlation when clusters are small. | Always use leave-one-user-out *or* better: user-level tests that never reuse the same unit. |
| M2 | LOO Spearman is still **biased negative** under the null (null mean ≈ −0.38 on 150 users / K=4) because excluding a strong user lowers LOO cluster acc. | **Do not** gate go/no-go on LOO Spearman > 0. Use **permutation Kruskal–Wallis** (or permute cluster labels) with p-value. |
| M3 | Small val caps (40 users) can flip go/no-go vs 150 users. Fragile `go` is not evidence. | Confirm E0 on large-cap (≥100–150 users) before E1. |
| M4 | `argsort(argsort(x))` ranks are wrong under ties; rating accuracy is heavily tied. | Use average (fractional) ranks for Spearman. |
| M5 | Shuffle control must permute **val assignments**, not only train labels (otherwise OOD assign via centroids is unchanged). | Keep E0 shuffle as post-assign permutation on val. |
| M6 | On E1 live (40 val users × 8 reviews) **R_worst_val saturated at 0.5** for both arms — step size too coarse for Р11. | E1 val/test caps ≥ **120 users**. Log bootstrap-CI later if still tied. |
| M7 | Point-δ anchor gate at \|D_anchor\|=50 is a **hair trigger**: 1 example = 1/50 = 0.02 = the whole tolerance, so it tolerates exactly one flip. D_anchor is built from confidently-solved cells → sits at a ceiling → noise is **one-sided downward**, so same-quality prompts get rejected by regression to the mean. Live C1: 49/50→47/50 (p≈0.25, not significant) killed a candidate worth CVaR 0.646→0.690, R_worst 0.4→0.5. | Implement Р15 literally: δ is a **tolerance band**, floored at 2 examples; reject only if the drop also passes **exact one-sided McNemar** (α=0.05). Raise \|D_anchor\| to **100** — at 50 the significance test needs −0.10 to fire (no usable operating point). `prime/experiment/anchor_gate.py`. |
| M9 | `R_worst` = 10th percentile of per-user accuracies, and each user has only 8 reviews → per-user accuracy is quantized to 1/8 steps, so the percentile is a step function. Raising val/test caps to 120 users did **not** unstick it: live cvar_lex logged R_worst_val = 0.500 in all 3 cycles. Zero variance also makes `proxy_validation.spearman` undefined (`null` in `summary.json`). | M6's fix is insufficient — the problem is per-user resolution, not user count. Either raise `max_reviews_per_user`, or report a continuous tail statistic (e.g. mean of worst-decile user accuracies / bootstrap CI) and drop `R_worst` from the selection key. |
| M13 | **Concrete sample sizes for a powered comparison** (paired design, per-user delta SD = 0.159 measured between the initial and evolved prompt on the same 120 users): detecting a **0.05** effect on `R_global` needs ~**79** users, **0.03** needs ~**220**, **0.02** needs ~**496**, **0.01** needs ~2000. Cluster-level tail metrics need far more because each cluster holds only a fifth of the users. | 120 users was never enough for the effects this system produces. Budget the test split from a target effect size, not from cost: ~240 users is the cheapest defensible cap and buys 0.03 on `R_global`. Recompute with `scripts/headroom_audit.py --eval ... --compare ...` before every campaign. |
| M10 | **The pair is underpowered by an order of magnitude.** Paired bootstrap over the same 120 test users (`scripts/paired_significance.py`): bootstrap SD is 0.020 for `R_global` and 0.035 for `CVaR_cluster`, so the minimum detectable effect at ~80% power is **0.056 / 0.099**. Every effect we have measured is 0.02–0.04 (cvar vs initial: R −0.021 p=0.147; CVaR −0.028 p=0.741; McNemar on examples p=0.100). Test `CVaR_cluster` across five nominally equivalent configurations spans 0.545–0.587 (SD 0.015) — run-to-run noise is the same size as every conclusion. | Do not report point estimates or arm-vs-arm winners at these caps. Always run the paired bootstrap; raise `max_reviews_per_user` (M9) and test users before the next comparison; treat all four completed E1 runs as mechanism diagnostics, not effect estimates. |
| M11 | ~~**`CVaR_cluster` is degenerate at K=5**~~ — **corrected, this was my analysis error, not a system defect.** The runs use `fitness.cvar_quantile = 0.33`, so `ceil(0.33×5) = 2` clusters are averaged. The "degeneracy" came from my own scripts defaulting to `active_learning.tail_quantile = 0.2`; recomputed at q=0.33 the test values are 0.5668 / 0.5486, not 0.5375 / 0.5096. The real defect in the same place is **M14**: the "shrunk" variant was not shrinking. | Keep `cvar_quantile ≥ 2/K`, now enforced in `PrimeConfig.validate`. Always pass the config's quantile into analysis scripts — a default in a helper silently redefined the headline metric across a whole postmortem. |
| M12 | **The significance anchor gate has no operating point** at the flip counts it actually sees. cvar C2: 0 improved / 4 worsened, exact one-sided p = 2⁻⁴ = **0.0625 > α=0.05** — mathematically unable to reject. C3: 1/6, p = 0.0625 again. So anchor accuracy decayed 0.95→0.91→0.90 with 0–1 improvements against 4–6 regressions and was accepted as `tolerated_noise` both times. `min_detectable_worsened: 5` is already in the artifact. Note the decay was the only in-run signal tracking the test outcome (global rose to 0.97 and held its test numbers). | Replace the point test with a **CI-based tolerance**: reject if the upper bound of the bootstrap CI on the drop exceeds δ. Or demote the gate to a monitor and use the anchor trend as a selection tiebreak. Do not read `accepted: true` as "no regression". |
| M14 | **Shrinkage, not a wider quantile, is what makes the tail measurable** (E-C, `scripts/exp_tail_metric_stability.py`, bootstrap over the 120 test users). Discriminability \|effect\|/SD: `shrunk_min w=25` **1.49** (SD 0.0217), `shrunk_min w=10` 1.45, `R_global` 1.04, `CVaR q=0.4` 0.63, `R_worst`/`CVaR q=0.2` 0.79, `R_tail q=0.2` 0.48, `R_tail q=0.4` **0.29**. Widening the quantile lowers SD but kills the effect faster, so it makes things *worse* — the opposite of what M11 recommended. Shrinking toward the grand mean lowers SD **and** enlarges the effect. Separately, the shipped `smoothed_cluster_accuracies` used Beta(1,1) — a prior worth 2 pseudo-examples toward 0.5 — which moves a 48-example cluster by ~4%: `CVaR_cluster_shrunk` was never meaningfully shrunk. | Shrink toward the **grand mean** with `fitness.shrink_prior_weight` ≈ the mean cluster size (shrink factor ≈ 0.5). Drop `R_tail` as the val selection key — it is the worst discriminator we measured, and it was the default. Required test users scale as (2.8/ratio)²: ~420 at ratio 1.49 versus ~1500 at 0.79. |
| M15 | **The objective's own noise is larger than everything the search achieved.** Scoring one fixed prompt on the same D_select three times with the cache bypassed (E-A, `scripts/exp_fitness_noise.py`, workers at temperature 0): `fitness_scalar` = 0.5237 / 0.5824 / 0.5514, **SD 0.0294, range 0.0587**. The whole cvar run moved 0.527 → 0.585 (+0.058) over three cycles, and cycles 2–3 contributed +0.002 and +0.003. Only 9–12 of 240 predictions flip between repeats (4–5%), but `R_global` SD is **0.0024** — 12× smaller — because the CVaR reads the worst 2 of 5 clusters, so a handful of flips landing in one small cluster swings it. This single fact explains the stalls, `best_selection_cycle = 1` in both arms, frozen champions, and why extra mutation budget hurt (O20): more draws from a noisy ranking select a higher noise order-statistic. | Stop attributing stalls to the search. Report every candidate comparison against this floor. The cure is variance, in this order: shrink toward the grand mean (≈2× free), enlarge D_select (√n), and spend budget on evaluation rather than iterations — O20 already showed the iterations were not buying generalisation. Note the arm comparison was never fair: `global` optimised a metric with 12× less noise than `cvar_lex`. |
| M16 | **A single-worker cascade screen does not reproduce the ensemble ranking** (E-B, `scripts/exp_cascade_screen.py`; 20 real OpenEvolve programs spanning 0.479–0.585, re-scored with kimi-k2.5 on the same D_select): Spearman on fitness **−0.042**, on `R_global` +0.239, recall of the ensemble top-3 inside the screen top-3 **0/3**. But this cannot yet be read as "cascades don't work": by M15 the ensemble ranking it is validated against is itself largely noise (SD 0.029 against a 0.106 spread), so no screen could reproduce it. | Do not build the cascade now. Re-run E-B after the variance fixes, against a ranking that is actually stable. Until then, buy precision with a bigger D_select rather than with a cheaper screen. |

| P9 | **Champion archive replaces the dominance front** (refines P7). With 5–6 noisy cluster axes almost every candidate is non-dominated, so `pareto_front`+`trim_front` filled the carried set with noise-lucky prompts and could evict the scalar-best (O18). New rule: fixed slots — [0] scalar-best (never evicted), then one champion per cluster on **shrunk** D_select accuracy; incumbents keep slots unless beaten by > `champion_margin` (0.01). The archive is memory + OE seed + consolidator feedstock; the heir is still the scalar-best (P7 unchanged). Implemented as `champion_archive` in `prime/consolidation/pareto.py`; dominance functions kept for ablation. |
| P8 | **Few-shot examples are pipeline-injected, not LLM-invented (Phase 2a / O22/O29).** Soft coaching alone failed (O22: 0–1/6 real). `inject_verbatim_fewshot` owns `<FewShotExamples>`; mutator targets `<DynamicRules>`. Legacy `synthetic_fewshot_generator` stays unported. |
| P6 | **D_anchor gate is a constraint, not a second objective.** Significance-based (McNemar, α=0.05) with δ floored at 2 examples; \|D_anchor\|=100. No weighted mixing with D_select gains (that is `v1_weighted`, an ablation arm only — M8). Rejected candidates are kept as `al_iter_*/rejected_by_anchor_gate.txt`, and the rejection counter goes into `summary.anchor_gate` (Р15). |
