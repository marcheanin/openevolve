# PRIME v2 — Group-Robust Prompt Evolution (новая итерация проекта)

Вторая итерация проекта PRIME. Предыдущая реализация и все эксперименты v1 лежат в
`../wilds_active_learn_approach/` (папка сохраняется как есть, для истории и переиспользования кода).

Этот документ: (1) что было в v1 и какие результаты, (2) с чем столкнулись — рецензии +
собственные находки, (3) ландшафт существующих работ, (4) новое позиционирование,
(5) редизайн архитектуры по этапам, (6) план экспериментов с приоритетами и go/no-go,
(7) ближайшие шаги, (8) риски.

## 1. Что было: PRIME v1 (кратко)

**Идея v1:** prompt-only адаптация замороженного ансамбля LLM (gpt-4o-mini,
gemini-2.5-flash, claude-3.5-haiku, majority vote) через эволюцию структурного промпта
(OpenEvolve/AlphaEvolve, мутатор gemini-2.5-pro) + active learning контроллер:
Hard/Anchor батчи (80, ρ=0.7), pool expansion, консолидация правил между циклами,
опциональная синтетика few-shot. Бенчмарк: Amazon-WILDS (5-way sentiment, user shift).

**Заявленный результат v1 (статья ACL ARR May'26, submission 5730):**
R_worst 50.00→55.91, R_global 71.30→75.41 на «полном тесте 34 533», «обгоняем LISA (54.7)».

**Ключевые артефакты v1:**
- Статья: `_ACL_ARR_May_26_PRIME.pdf` (в `mipt/diploma/`)
- Код: `../wilds_active_learn_approach/{active_loop,data_manager,evaluator,workers}.py`
- Сравнительная таблица: `../wilds_active_learn_approach/last_four_experiments_comparison.md`
- Главный прогон: `results_all_categories_evolve_subsample/fulltest_al_iter_5/`
- Uncapped-AL прогон: `results_all_categories_uncapped_train/` (см. `README_UNCAP_AL.md`)
- Fair-baselines (один GPT-4o-mini): `results_evoprompt_full_seed42/`, `results_apo_full/`, `results_opro_full/`

## 2. С чем столкнулись

### 2.1 Рецензии (ARR May'26: Overall 2.5 / 2 / 2, Soundness 2.5 / 2.5 / 2)

Конвергентные претензии всех трёх рецензентов:

1. **«Prompt-only бьёт SOTA fine-tuning» — невалидное сравнение** (M2QJ W1, tn7Y W3):
   frontier-ансамбль против 66M DistilBERT — это про масштаб бэкбона; плюс тест-сет не官
   официальный (см. 2.2).
2. **Вырожденный baseline** (M2QJ W2): стартовый ансамбль (50.0) хуже одиночного
   gpt-4o-mini (53.18) → прирост во многом «восстановление из плохого промпта».
3. **Один датасет / задача / язык** (все трое).
4. **Нет сидов и CI** (tn7Y): выигрыш над LISA 1.2 пп ≈ собственный заявленный шум 0.5–1.0 пп.
5. **Новизна инженерная** — комбинация известных компонент (все трое).
6. **κ циркулярен** (M2QJ): согласие оптимизируется в fitness → его рост не является
   независимым свидетельством.
7. **Абляции на прокси-метриках** (M2QJ W4): synthetic-абляция на Hard-pool accuracy,
   AL-сравнение на discovery-сплите — никогда на headline-метрике.
8. **τ=0 обессмысливает disagreement score** (tn7Y).
9. Мелочи: нестыковка числа циклов (5/8/7 в тексте/таблице/рисунке), tie-breaking
   majority vote не описан, mutator-токены оценены а не измерены, артефакты не выложены.

### 2.2 Собственные находки (глубже рецензий)

- **Сплит кастомный, не официальный WILDS.** `wilds_experiment/evaluator.py::create_splits_from_preprocessed`
  режет `get_subset('train')` по пользователям 70/15/15 (seed 42). «Тест 34 533» — наша
  собственная тестовая доля train-пользователей WILDS. Числа ERM/GroupDRO/LISA взяты с
  официального OOD-теста → сравнение некорректно. (Внутри пайплайна сплиты user-disjoint,
  утечки промпт-отбора на тест нет — но это не спасает сравнение с лидербордом.)
- **Собственные fair-baselines подрывают headline.** Из `last_four_experiments_comparison.md`:
  EvoPrompt на одном GPT-4o-mini даёт **R_worst 56.50** против ансамблевого PRIME **55.91**
  (single-PRIME 56.80). По первичной метрике преимущество PRIME над честным одномодельным
  оптимизатором — в пределах шума. PRIME выигрывает по R_global/MAE/κ, но не по тому,
  вокруг чего построена статья v1.
- **Причина системная:** PRIME v1 нигде не оптимизирует worst-group. Fitness =
  глобальная точность на батче; R_worst входит только в межцикловый selection с весом 0.15.
  Метод агностичен к группам — ожидать систематического выигрыша по групповой метрике
  не было оснований.
- **Одноточечное бутылочное горлышко между циклами.** MAP-Elites архив сбрасывается
  каждый цикл (`active_loop.py:784`), в следующий цикл переходит ровно один промпт
  (консолидированный или evolution-best). Это противоречит и мотивации MAP-Elites, и
  Pareto-фронту GEPA; синхронный обвал на цикле 4 в v1 — ожидаемое поведение такого дизайна.
- **Структурный промпт не измерен.** Рецензентам идея понравилась, но абляции
  structured-vs-monolithic нет; claim про «catastrophic forgetting in prompt space» ничем
  не подтверждён.
- **Магические веса.** (w1,w2,w3)=(0.5,0.3,0.2), λ_w=0.15, λ_σ=0.30 — «подобраны на
  пилоте», сетки нет.

## 4. Новое позиционирование (v2)

**Тезис:** generic prompt optimization улучшает среднее, но не хвост распределения по
группам (мотивируется PfR-выводами про ICL и нашими же EvoPrompt-цифрами v1 — слабость v1
становится мотивирующим результатом v2). Мы делаем **первую group-aware эволюцию промпта**:
DRO-объектив и group-aware acquisition в prompt-space.

**Ключевое проектное решение (согласовано): группа = стилевой кластер пользователя, не user_id.**
Тестовые пользователи в WILDS не встречаются в train → переносимы только обобщаемые
свойства (стиль, многословность, сарказм, калибровка оценок). Строим user-профили
(эмбеддинг отзывов + rating-статистики: средняя оценка, дисперсия, длина) → k кластеров
(6–10). Train- и test-юзеры маппятся в одно пространство кластеров → робастность по
кластерам переносима. Кластеры также решают проблему шума (CVaR по кластерам из 10–15
примеров вместо юзеров из 2–4).

**Страховка (study-фрейминг):** если group-aware механика не даст статзначимого прироста,
статья остаётся защищаемой как первое систематическое исследование дискретных
prompt-оптимизаторов под сдвигом (E9–E10 ниже) с честным negative/mixed result по методу.

**Вторичные ветки (не в заголовок):**
- label-lean/label-free режим: acquisition по d_score работает без gold; полный label-free
  конфликтует с DRO-fitness (нужны метки) → раздел/future work, не headline;
- LoRA-сравнение на открытом бэкбоне (Qwen3-8B) при равных данных — честная версия
  «prompt vs weights» вместо снятого claim'а про DistilBERT-LISA.

## 5. Редизайн архитектуры по этапам

### 5.0 Данные и протокол (фундамент)
- **Официальный WILDS OOD-сплит** вместо кастомного 70/15/15. Все headline-числа — на нём.
  Строки ERM/GroupDRO/LISA становятся честно сравнимыми.
- Один раз: user-профили + кластеризатор стилей (общий для всех этапов ниже).
- Bootstrap-CI по пользователям, 3 сида для headline-чисел, paired-сравнения на общем тесте.
- Зафиксировать tie-breaking majority vote; логировать mutator-токены (не оценивать).

### 5.1 Acquisition → group-coverage + ранжирование вместо порога
- Убрать бинарный τ. Каждому примеру — continuous score; Hard-слот = top-k по score
  (с oversample ×3) → k-means diversity **внутри** топа; Anchor = низ score, стратификация
  по звёздам × кластерам.
- Формула score без магических констант — **лексикографическая**: сортировка по паре
  (err_i, d_i): сначала ошибки (внутри — по убыванию d), затем верные по убыванию d.
  Альтернатива в абляцию: ordinal ensemble loss = mean(|vote_m − gold|)/scale (OHEM-стиль,
  один естественный скаляр). Взвешенные суммы — только с сеткой чувствительности.
- **Групповые квоты:** вес кластера в Hard-слоте ∝ (1 − acc_кластера) на Seen.
- Label-free вариант acquisition = чистый d_i (Query-by-Committee, Seung'92) — тот же код.
- Expansion: вместо farthest-from-anchor — кандидаты из Unseen с высоким d_i после одного
  прогона, с покрытием кластеров (Cluster-Margin-стиль).

### 5.2 Fitness (inner loop) → CVaR по кластерам
`fitness = α·CVaR_cluster_acc + β·Acc_global + γ·κ − P_len`,
где CVaR = средняя точность худшей трети стилевых кластеров в батче (не строгий минимум —
шум). В батче 5–8 кластеров по 10–15 примеров. κ оставить с малым весом, но в статье
не подавать его рост как независимое свидетельство (урок v1).

### 5.3 Фидбек мутатору → групповой разрез
Error report с разбивкой по кластерам («кластер C3: краткие эмоциональные, acc 0.41,
типичная ошибка gold=2→pred=4»). Разрешить мутатору **style-conditional правила**
(«если отзыв краткий и гиперболизированный — проверь на сарказм прежде чем ставить 5»).
Это механическая связь промпта с групповой структурой + интерпретируемый артефакт.

### 5.4 Синтетика few-shot → стилевые близнецы
Генерировать boundary-пары **в стиле худшего кластера**, а не только по confusion-парам.
Абляция модуля — на headline-метрике (урок M2QJ W4).

### 5.5 Структурный промпт — оставить, понизить в статусе
Оставить как механизм (дисциплинирует мутатора, локальные диффы, секция под
style-conditional правила, интерпретируемость), **убрать из contributions**.
Добавить абляцию structured-vs-monolithic (1 сид, capped). Если выигрыша нет —
формулировка «структура для контролируемости и интерпретируемости, не для точности».
Двухуровневую политику (заморозка BaseGuidelines внутри цикла) — тоже в абляционную
лестницу: claim про forgetting в v1 не измерен.

### 5.6 Консолидация → пул вместо точки (исправление дефекта v1)
Проблема v1: архив сбрасывается каждый цикл, между циклами передаётся один промпт —
одноточечное бутылочное горлышко, уничтожающее разнообразие (противоречит MAP-Elites и
Pareto-мотивации GEPA; объясняет обвал цикла 4).
Изменения:
1. **Переносить top-k (3–5) промптов** из архива как стартовую популяцию следующего цикла.
2. **Консолидированный промпт — кандидат в пуле**, а не единственный наследник
   (эволюция сама его поднимет, если он хорош); гейт остаётся фильтром от мусора.
3. **Pareto по кластерам:** держать промпты, лучшие на разных стилевых кластерах;
   консолидация = слияние комплементарных уроков (мутатору сообщается, какие правила
   за какой кластер отвечают). Абляция: collapse-to-one (v1) vs pool-carryover vs
   cluster-Pareto.

### 5.7 Selection между циклами
Первичный критерий — CVaR_val по кластерам (лексикографически: сначала CVaR, при
близости — global). Consolidation-гейт: не принимать промпт, ухудшивший любой нижний
кластер сверх допуска (анти-forgetting по группам).

### 5.8 Ансамбль
Не менять (изоляция вкладов). Репортить per-worker разрез по кластерам как анализ.
Взвешивание воркеров по кластерам — future work.

## 6. План экспериментов

### Ядро (метод-фрейминг), в порядке приоритета

- **E1 — ПИЛОТ (go/no-go, делать первым):** fitness global vs CVaR-cluster, всё
  остальное фиксировано, 1 сид, capped test (~600). Бюджет ≈ один обычный AL-прогон
  (~$25–30, ~6–9 ч). Если CVaR не двигает worst-метрики → переключение на study-фрейминг
  (E9–E10 ядро), экономим месяцы.
- **E2 — компонентная лестница (главная таблица):** plain evolution → +AL(v1) →
  +group-acquisition → +CVaR-fitness → +style-conditional feedback → +pool-carryover →
  full v2. Официальный тест, 3 сида, bootstrap-CI. Одновременно ответ на M2QJ W4.
- **E3 — baselines на равном бюджете:** EvoPrompt, APO, OPRO (готовы из v1 — перегнать
  на официальном сплите), GEPA (код открыт), few-shot ICL, zero-shot, PfR-style;
  справочно ERM/GroupDRO/LISA (теперь честно).
- **E4 — второй бенчмарк: CivilComments-WILDS** (согласовано). Группы = identity-атрибуты,
  прямое сравнение с PfR. Бонус: там группы oracle-известны → метод показываем в двух
  режимах (oracle-группы на CivilComments, inferred-кластеры на Amazon).
- **E5 — ID-vs-OOD gap:** каждый промпт оценить на held-out отзывах train-юзеров и на
  test-юзерах. Гипотеза: у generic-оптимизаторов gap больше. Дёшево, убедительно.

### Целостность и анализ (в обоих фреймингах)
- **E6 — чувствительность:** k кластеров ∈ {4,8,12}, CVaR-квантиль ∈ {25%,33%,50%},
  1 сид, capped. Закрывает «новые магические числа».
- **E7 — качественный разбор:** появившиеся style-conditional правила, per-cluster
  confusion до/после, история эволюции промпта.
- **E8 — статистика:** paired bootstrap по пользователям, mean±std по 3 сидам, отчёт
  о вариативности между сидами.
- **E-абляции структуры (из раздела 5.5–5.6):** structured vs monolithic;
  collapse-to-one vs pool-carryover vs cluster-Pareto; two-level vs flat mutation.
  1 сид capped, победители — в основной конфиг до дорогих прогонов.

### Study-фрейминг (страховка или основа — по результату E1)
- **E9 — систематическая оценка оптимизаторов под сдвигом:** {APO, OPRO, EvoPrompt,
  GEPA, SPO} × {Amazon-WILDS, CivilComments} × {avg acc, worst-group, ID→OOD gap}.
  Тезис: «оптимизаторы улучшают среднее, не хвост, и оверфитятся на распределение
  оптимизации». Цитируемый результат сам по себе.
- **E10 — декомпозиция сдвига:** category-shift внутри Amazon (эволюция на Books-heavy
  пуле → тест на прочих категориях) — второй тип сдвига почти бесплатно.

### Вторичные ветки (если бюджет позволит)
- **Label-budget кривая:** N gold-меток ∈ {0, 25, 100, 400}; при N=0 acquisition = d_i,
  fitness = κ + stability − KL(распределение предсказаний ‖ прайор) (анти-mode-collapse).
  Baselines: SPO. Раздел, не headline.
- **LoRA на Qwen3-8B:** (а) zero-shot, (б) +PRIME-промпт, (в) LoRA на тех же N метках,
  (г) LoRA на полном train — честная версия «prompt vs weights», точки на той же
  label-budget кривой.

### Порядок работ
1. Инфраструктура: официальный сплит + user-профили/кластеризатор + bootstrap-CI
   (без LLM-затрат).
2. E1-пилот → решение о фрейминге.
3. Дешёвые абляции структуры/консолидации (1 сид, capped) → зафиксировать конфиг v2.
4. E2 + E3 на официальном тесте, 3 сида.
5. E4 (CivilComments), E5, E6–E8.
6. E9–E10 / вторичные ветки — по бюджету и результату E1.

## 8. Риски

1. **E1 может не показать эффект** (вероятность ~30–40%): CVaR на батче шумнее глобальной
   точности. Смягчение: кластеры вместо юзеров, треть вместо минимума, батч-квоты.
   План Б — study-фрейминг (E9 ядром), заложен в дизайн.
2. **Стилевые кластеры могут не захватить ось сдвига** (вдруг сдвиг — в калибровке оценок,
   не в стиле) → в профиль обязательно включены rating-статистики; E6 проверяет k.
3. **Effect size 1–2 пп** → без 3 сидов и bootstrap не защищается; бюджет на повторы
   закладывается заранее.
4. **GEPA/SPO baselines** — интеграционные затраты; если не влезут, минимум = EvoPrompt/APO/OPRO
   (уже есть) + ICL, а GEPA — в E9.
5. **CivilComments** — токсичность, другой класс-баланс; смоук обязателен до полного прогона.
