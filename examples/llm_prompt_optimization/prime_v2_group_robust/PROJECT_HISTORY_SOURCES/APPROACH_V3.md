# GRAPE v3: критическая ревизия концепции и согласованная архитектура под OOD

Статус: ревизия APPROACH.md (v2) целиком. Правило документа: **ни один компонент
не сохраняется «потому что так было»** — каждый либо выводится из цели, либо
удаляется/заменяется. Цель зафиксирована одна:

> Максимизировать качество на **худшем хвосте групп** для **не виденных при
> оптимизации источников**, меняя только текстовый промпт, при бюджете API-вызовов B.

Из неё следуют три инварианта, через которые проверяется каждый механизм:

- **I1 (тип, не носитель).** Всё, что оптимизируется, должно быть «правилом про
  тип источника», а не про конкретный источник. Механизм, который может
  вознаграждать запоминание конкретных рецензентов, — дефектен.
- **I2 (хвост, не среднее).** Любой отбор (кандидатов, примеров, элитов) должен
  быть устроен так, чтобы прогресс на слабой группе не «усреднялся» прогрессом
  на сильных.
- **I3 (бюджет = вызовы API).** Дефицитный ресурс — не метки (train размечен),
  а вызовы замороженного ансамбля. Экономить нужно именно их, и тратить там,
  где решение о кандидате наиболее информативно.

## 1. Ревизия компонентов

Формат: роль → критика v2 → решение v3.

### 1.1 Кластеризация (вывод групп)

**Роль.** Определить, что такое «группа», — от этого зависит и объектив (CVaR по
группам), и селекция, и весь нарратив.

**Критика v2.**

1. *Двухпространственная шизофрения.* k-means фитится в **full**-проекции
   (с rating-статистиками), а назначение на val/test/deploy идёт в **label-free**
   проекции к отдельно посчитанным центроидам. Кластеры живут в одной геометрии,
   используются в другой. `train_projection_agreement < 0.5` лишь печатает
   warning — система продолжает работать с группами, которые заведомо
   не переносятся. Это нарушение I1 в самом основании: если тип нельзя
   распознать label-free, он не существует на деплое.
2. *Статичность.* Кластеры фитятся один раз; прокси-валидация
   (corr CVaR_cluster ↔ R_worst) — только лог, не управляющий сигнал.
3. *Утечка в новой схеме данных.* Если селекционный набор строится из
   отложенных источников (см. §1.3), эти источники не должны участвовать
   в fit кластеров — иначе центроиды «видели» held-out.

**Решение v3.**

- **Fit сразу в label-free пространстве** (embedding PCA + длина/пунктуация/caps,
  без rating-статистик). Одна геометрия для train, val, test и деплоя;
  двухпроекционная механика упраздняется. Rating-статистики не выбрасываются,
  а меняют роль: **внешняя валидация кластеров** (ANOVA mean_rating по кластерам,
  согласованность со стилевыми осями) — сигнал «кластеры содержательны»,
  не участвующий в геометрии.
- Кластеры фитятся **только на fit-источниках** (см. разбиение §1.3).
- **Прокси-валидация становится гейтом с ремонтом**: если после N циклов
  corr(CVaR_cluster, R_worst_val) < порога — остановка, перефит с другим K /
  признаками, а не продолжение дорогой эволюции по бессмысленным осям.
- Выбор K: silhouette + стабильность по сидам (как в v2) **плюс** ограничение
  статистической мощности: K не больше, чем позволяет
  |D_select| / (минимум примеров на группу для оценки Acc_k с нужным CI).
  Осмысленные оси важнее тонкой сегментации.

Бонус для режима B (§1.9): роутер работает ровно в том пространстве, где кластеры
фитились, — несоответствие проекций исчезает по построению.

### 1.2 Ансамбль и сигналы

**Роль.** Замороженный предиктор; источник d_i (label-free информативность) и κ.

**Критика v2.**

1. *Majority vote + tie_break="lowest_rating" на порядковой шкале* — произвол.
   Для ординальных меток медиана голосов — состоятельная агрегация без
   магического тай-брейка.
2. *κ в fitness — легаси v1 и он вреден.* κ измеряет согласие воркеров, не
   правильность. Промпт, продавливающий всех к «3», получает высокий κ.
   Компонента objective, которую можно удовлетворить деградацией, — не
   компонента objective.
3. *d_i зависит от текущего промпта.* Это не свойство примера, а свойство пары
   (пример, промпт). Для наведения мутатора это нормально; для любых
   персистентных решений (состав селекционного набора) — нет.

**Решение v3.**

- Агрегация: **медиана** (для нечётного M — средний голос; конфиг-опция,
  majority остаётся как абляция).
- **κ исключается из fitness**, остаётся диагностикой (детектор коллапса
  ансамбля в логах).
- d_i используется только в короткоживущих решениях (минибатчи мутатора,
  label-lean подпитка), никогда — в персистентных наборах.

### 1.3 Роли данных (упразднение AL-пула)

**Роль.** Что показывать мутатору, чем мерить кандидатов, чем охранять регресс.

**Критика v2 (главный блок ревизии).**

Seen/Unseen/hard/anchor — машинерия активного обучения, спроектированная под
дефицит **меток**. Наш дефицит — **вызовы** (I3). При этом один активный батч
(~80, замороженный на весь внутренний цикл) выполняет четыре несовместимые роли:

- сигнал мутатору (нужна адверсариальность) —
- критерий приёмки/fitness (нужна несмещённость) —
- оси MAP-Elites (нужна стабильность) —
- регрессионный якорь (нужна персистентность).

Следствия: Goodhart на 80 примерах внутри цикла; несравнимость fitness между
циклами (батчи разные, а carryover сортирует их как сопоставимые); Acc_k,
систематически заниженный hard-квотами и неравномерно по группам — и поверх
него CVaR по худшим группам; дескрипторы MAP-Elites с шагом квантования 0.1
при feature_bins=5. Ни одна из ролей не выполняется хорошо.

**Решение v3 — четыре набора с непересекающимися ролями.**

Сначала **разбиение по источникам**: train-источники делятся на
`fit_sources` (кластеризация, минибатчи мутатора) и `heldout_sources`
(селекция). Это внутренняя репетиция деплоя: правило считается выученным,
только если работает на *других носителях того же типа* (I1).

| Набор | Состав | Обновление | Роль | Допустимое смещение |
|---|---|---|---|---|
| **D_mut** | 30–40 прим. из fit_sources; квоты ∝ (1−Acc_k), ранг (err, d), diversity | заново на каждую мутацию | error artifacts мутатору + локальный тест «лучше родителя?» | адверсариальное — желательно |
| **D_select** | 300–500 прим. из heldout_sources, стратификация по группам (назначение label-free) | фиксирован на ран | fitness, CVaR, дескрипторы QD, Парето-фронт, carryover | никакого |
| **D_anchor** | ~100 прим., ячейки группа×класс из уверенно решённых | фиксирован на ран | регрессионный гейт при приёмке | консервативное |
| **U** | неразмеченный резервуар | по требованию | подпитка D_mut по d_i (label-lean) | — |

Каждая квота/эвристика v2 переезжает туда, где её смещение полезно:
group-квоты и (err,d)-ранжирование → **только D_mut**; стратификация → D_select;
anchor-идея → отдельный сьют с гейтом вместо 30% разбавления батча;
expansion по d_i → подпитка D_mut. Классы `AcquisitionPool.hard/anchor`
и бинарный `err>0 or d>0` упраздняются без замены — их функцию берут роли.

**Каскад бюджета (I3):**

1. Мутация → оценка на своём D_mut (~35×M вызовов). Хуже родителя на минибатче → отброс.
2. Прошёл → шард D_select (25–33%). Вне зоны фронта (с учётом CI) → отброс.
3. Выжил → полный D_select + гейт D_anchor → запись в архив/фронт.

Полную оценку получают ~10–20% кандидатов; сэкономленный бюджет → больше
мутаций. Кэш (hash(prompt), example_id) → предсказание: воркеры при T=0
детерминированы, повторные оценки бесплатны.

### 1.4 Fitness

**Критика v2.**

1. Смесь `w_c·CVaR + w_g·global + w_k·κ` — «магические веса», против которых
   документ сам возражает, вводя лексикографическую селекцию между циклами.
   Непоследовательность: внутри цикла веса, между циклами — lex.
2. κ — см. §1.2, исключён.
3. Acc_k без сглаживания на малых группах: шум напрямую в CVaR и в оси архива.

**Решение v3.**

- Скаляр для OpenEvolve — **лексикографическая аппроксимация**:
  `fitness = CVaR_shrunk + ε·Acc_global − penalty_len`, ε≈0.01 (тай-брейк,
  не компромисс). Режимы `global`/`v1_weighted` остаются только как абляции E1.
- **Сглаживание**: `Acc_k = (correct_k + a) / (n_k + a + b)` (Beta-prior,
  a=b=1); CVaR — по сглаженным значениям; в логах — бутстрэп-CI.
- length_penalty сохраняется с новой мотивировкой: это не только стоимость,
  но и OOD-регуляризатор (длинный промпт = много узких правил = оверфит
  на источники оптимизации).

### 1.5 Эволюция и структурный промпт

**Критика v2.**

1. Scoped-мутации навязываются **только текстом system message** — ничто не
   проверяет, что мутатор действительно правил один блок. Дисциплина без
   энфорсмента — это пожелание.
2. Артефакты ошибок описывают один батч; уроки предков (accumulated lessons,
   как в GEPA) не передаются явно.

**Решение v3.**

- **Структурный валидатор мутаций**: после мутации diff по блокам
  (`prompt_blocks.extract_block`); изменение >1 блока, порча `<Task>`/тегов,
  правка `<BaseGuidelines>` вне консолидации → мутация отклоняется до всякой
  оценки (0 вызовов API — самый дешёвый фильтр в системе).
- В артефакты добавляется краткий **changelog правил** линии предков
  (какие правила когда добавлены и какую группу чинили) — прямой аналог
  накопленных уроков GEPA, синергия со scoped-блоками.
- Двухшкальная структура (Base медленно / DynamicRules быстро / FewShot под
  худшие группы) подтверждается ревизией: это носитель credit assignment
  и точка стыковки с per-group фронтом и консолидацией. Сохраняется.

### 1.6 QD-архив и селекция кандидатов

**Критика v2.**

1. Дескрипторы с шумного батча → дребезг ячеек (см. §1.3).
2. При K=8 и bins=5 сетка имеет 5⁹ ≈ 2M ячеек при популяции 8–30 — это не
   «освещённая карта», а разреженный словарь. Честнее так и проектировать.
3. `cluster_pareto` применяется только к carryover между циклами; внутри цикла
   селекция родителя — дефолт OpenEvolve, никак не связанный с группами.

**Решение v3.**

- Дескрипторы — со **шарда/полного D_select**, сглаженные; bins=3
  (слабая/средняя/сильная группа) — ячейки означают «профиль специализации»,
  а не шум.
- **Per-group Парето-фронт как первичная структура** (GEPA per-instance,
  огрублённый до групп — потому что группы и есть ось нашей задачи):
  - кандидат живёт во фронте, если лучший (или в CI лучшего) хотя бы
    на одной группе по D_select;
  - **родитель для следующей мутации** сэмплируется с фронта с весом
    ∝ числу групп, где он лидирует (I2: специалист по слабой группе получает
    шанс размножиться, даже если его средний fitness низок);
  - MAP-Elites-сетка OpenEvolve остаётся реализацией хранения, фронт —
    логикой приёмки и селекции.
- Carryover между циклами = срез фронта (элита на группу + глобальный лучший),
  все fitness которого измерены на **одном и том же** D_select — сравнение
  корректно по построению.

### 1.7 Консолидация

**Критика v2.** Гейт `fitness ≥ best − δ` сравнивает точечные оценки на шумных
данных; при live-режиме консолидат мерится на val, остальные — на батче
(разные линейки).

**Решение v3.** Консолидат оценивается на D_select как обычный кандидат
(каскадом), гейт — **CI-aware**: принять, если нижняя граница CI консолидата
не хуже верхней границы CI лучшего минус δ, и D_anchor-гейт пройден.
Scope=BaseGuidelines и статус «кандидат, не наследник» — сохраняются
(согласуются с двухшкальной структурой и фронтом).

### 1.8 Иерархия оценки и сертификация

В v3 выстраивается **градиент стоимости и полномочий** (каждый уровень дороже
и авторитетнее предыдущего, ни один не подменяет другой):

| Уровень | Частота | Данные | Решение |
|---|---|---|---|
| D_mut | каждая мутация | fit_sources, адверсариальный срез | жив/мёртв локально |
| D_select (шард → полный) | каждый выживший кандидат | heldout_sources, стратифицирован | фронт, архив, carryover |
| Официальный val (WILDS OOD) | раз в AL-цикл | новые источники | межцикловой выбор промпта; прокси-гейт кластеров |
| Официальный test | один раз | новые источники | сертификация: R_worst, CVaR, бутстрэп-CI, ID-vs-OOD gap |

ID-vs-OOD gap перестаёт быть только финальной строчкой отчёта: его внутренняя
версия (fit_sources vs heldout_sources на D_select) логируется каждый цикл —
ранний детектор оверфита на источники оптимизации.

### 1.9 Спектр маршрутизации A/B/C

Ревизия подтверждает конструкцию §4.6 APPROACH и усиливает её: после перехода
на label-free fit кластеров (§1.1) режим B теряет главный технический риск —
рассинхрон пространства кластеризации и пространства роутинга. Страховки
(abstention-fallback, общая база, порог данных, оценка только с предсказанным
роутингом) — без изменений. Порядок: A — дефолт, B — после E1 и внедрения
ролей данных.

### 1.10 Label-lean режим

**Критика v2.** Label-lean заявлен как «та же механика при err=None», но новая
архитектура честно показывает: без меток невозможен D_select, а значит и
несмещённая селекция. Прятать это — самообман.

**Решение v3.** Label-lean — **отдельная экспериментальная ветка** с явно
ослабленными гарантиями (селекция по d_i-прокси + крошечный размеченный
D_select из десятков примеров), а не режим основного пайплайна. Основная
архитектура проектируется под «метки train есть, вызовы дороги».

## 2. Единая картина: как компоненты следуют из цели

Одна цепочка, каждое звено выводится из предыдущего:

1. **Деплой-метрика — хвост групп на новых источниках** → группа должна быть
   распознаваема без меток на деплое → **кластеры фитятся label-free** на
   поведенческих профилях (§1.1).
2. **Правила должны обобщаться на новых носителей типа** (I1) → селекционное
   давление обязано это измерять → **D_select из отложенных источников**,
   назначенных label-free (§1.3): условие деплоя воспроизведено внутри цикла.
3. **Оптимизируется хвост** (I2) → fitness = **CVaR по сглаженным Acc_k на
   D_select** с лексикографическим тай-брейком (§1.4); эволюции безразлична
   негладкость этого объектива — пара «DRO × эволюция» остаётся ядром новизны.
4. **Прогресс на слабой группе нельзя усреднить** (I2) → **per-group
   Парето-фронт** приёмки и селекции родителя + MAP-Elites-хранилище
   профилей специализации (§1.6).
5. **Мутатору нужно знать, где болит** → **D_mut**: свежий адверсариальный
   срез слабых групп с error artifacts и changelog предков (§1.3, §1.5) —
   смещение здесь работает на нас, потому что эти данные ничего не решают.
6. **Починка группы k не должна ломать группу j** → scoped-мутации со
   структурным энфорсментом + двухшкальный промпт + **D_anchor-гейт** (§1.5,
   §1.3) — три независимых механизма изоляции изменений.
7. **Специалистов нужно сливать, не теряя** → консолидация только
   `<BaseGuidelines>`, CI-aware гейт, консолидат — кандидат во фронт (§1.7).
8. **Бюджет — вызовы** (I3) → каскад D_mut → шард → полный D_select + кэш
   предсказаний (§1.3): дорогая, несмещённая оценка достаётся только тем,
   кто её заслужил дешёвыми фильтрами.
9. **Финальное слово** — официальные val (межцикловой арбитр) и test
   (одна сертификация с CI и ID-vs-OOD gap) (§1.8).

Что удалено без замены и почему: κ из fitness (удовлетворяется деградацией),
магическая смесь весов (противоречила собственной lex-логике), Seen/Unseen/
hard/anchor-пул (решал дефицит меток, которого нет), full-проекция кластеров
(группы, не распознаваемые label-free, не существуют на деплое), 30%
anchor-разбавление батча (слабая форма настоящего регрессионного сьюта),
бинарный префильтр err/d (уже признан дельтой 6), majority+tie-break
(медиана состоятельнее для ординальной шкалы).

## 3. План изменений в коде

### Фаза 0 — гигиена (дёшево, до экспериментов)

1. `fitness/objective.py`: режим `cvar_lex` (CVaR_shrunk + ε·global − len),
   κ убрать из всех режимов кроме абляционного `v1_weighted`;
   `fitness/metrics.py`: Beta-сглаживание Acc_k (параметры в конфиг), CI.
2. `workers/ensemble.py`: агрегатор `median` (конфиг `ensemble.aggregation`),
   majority — абляция. Удалить мёртвый `CandidateEvaluator._run_predict`
   (баг: `prompt_template=""`).
3. `configs/`: новый `base_v3.yaml` с ролями данных и каскадом.

## 4. Риски ревизии (честно)

- **Стоимость D_select.** 300–500 примеров × M воркеров на выжившего кандидата —
  заметно. Каскад и кэш обязаны это компенсировать; если бюджет не сходится,
  первым уменьшается частота полных оценок (шардовая оценка авторитетнее
  батчевой v2 в любом случае).
- **Меньше данных кластеризации.** Отделение heldout_sources сокращает
  материал для fit кластеров; при малом числе источников — конфликт с выбором K
  (лечится порогом мощности из §1.1).
- **Label-free fit может дать более слабые кластеры**, чем full-fit
  (rating-сигнал терялся из геометрии). Это осознанная плата за I1: группы,
  живущие только в rating-статистиках, всё равно бесполезны на деплое.
  Диагностика по rating-статистикам покажет, сколько содержательности потеряно.
- **Сложность per-group фронта поверх OpenEvolve.** Если интеграция с parent
  selection окажется инвазивной — fallback: серия коротких OpenEvolve-ранов
  с нашей селекцией между ними (архитектурно уже поддержано AL-циклами).
