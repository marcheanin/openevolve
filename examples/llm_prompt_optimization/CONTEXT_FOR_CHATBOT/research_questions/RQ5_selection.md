# RQ5 — Отбор: почему выбор по худшей группе ломается

## Вопрос

При обычном размере размеченной валидации способно ли правило отбора по худшей
группе ранжировать промпты так, чтобы ранжирование переносилось на тест?

## Короткий ответ

Нет, и хуже: оно систематически выбирает не то. На двух независимо порождённых
пулах все 6 правил, опирающихся на минимум по группам, **антикоррелируют** с
тестовым worst-group (Spearman −0.34 … −0.62). Все 12 усредняющих / group-free
правил неотрицательны. Замена одного лишь правила отбора двигает результат на
0.030 при полном разбросе матрицы методов 0.070.

Механизм: **идентичность** худшей группы оценивается надёжно, её **значение** —
нет (sd одной группы на D_dev = 0.0475 при решениях на разнице 0.040).

На Amazon знак антикорреляции hard_min **не** воспроизвёлся (ρ=+0.40); плохим
селектором оказался R_global (ρ=−0.16). Отбор ломается везде, но ломается
по-разному.

### F5. Swing правила на R15-пуле

Одни и те же 12 кандидатов, один D_dev, меняется только dev-статистика.
Тест = CVaR@25% на test_fixed_large (числа ниже — как в отчёте).

| dev rule | pick | test CVaR@25% | regret | Spearman vs test |
|----------|------|--------------:|-------:|-----------------:|
| mean GBA | `nl_lenient_max` | 0.6608 | 0.0008 | **+0.71** |
| worst-class (group-free) | `nl_lenient_max` | 0.6608 | 0.0008 | **+0.71** |
| global accuracy | `nl_lenient_max` | 0.6608 | 0.0008 | +0.63 |
| softmin shrunk (shipped) | `thr_p20` | 0.6592 | 0.0025 | +0.58 |
| CVaR@50% | `thr_p80` | 0.6583 | 0.0033 | +0.27 |
| CVaR@25% | `nl_strict` | 0.6317 | 0.0300 | **−0.34** |
| hard-min GBA | `nl_strict` | 0.6317 | 0.0300 | **−0.57** |

Swing только от правила = **0.030**. `nl_strict` — худший кандидат пула на тесте
(recall 0.849 / spec 0.539).

Правила по минимуму **антикоррелируют** с той целью, которую якобы оптимизируют.

### Почему: точность dev-статистик (bootstrap sd на seed, n=900)

| statistic | sd on D_dev |
|-----------|------------:|
| single group GBA (g8) | **0.0475** |
| hard-min GBA | 0.0401 |
| CVaR@25% | 0.0312 |
| softmin unshrunk | 0.0221 |
| softmin shrunk w=40 | 0.0180 |
| mean GBA | 0.0158 |
| global accuracy | 0.0150 |

Величина, от которой зависят все worst-group правила, несёт sd ≈ 0.048 — того же
порядка, что весь межметодный разброс.

Конкретный переворот: на D_dev `nl_strict` g8 = 0.610 vs `nl_lenient_max` 0.570
(+0.040, меньше 1 sd). На тесте ×6 больше: 0.603 vs **0.653**. Argmin-группа
стабильна (g8 и на dev, и на тесте) — не идентичность, а **значение**.

### F7. Репликация на пуле оптимизаторов (n=26)

| dev rule | pick | test CVaR@25% | regret | Spearman |
|----------|------|--------------:|-------:|---------:|
| worst-class | `44_evoprompt_de` | 0.6450 | 0.0225 | **+0.68** |
| mean GBA | `43_evoprompt_de` | 0.6275 | 0.0400 | +0.46 |
| global acc | `43_ape_k48` | 0.6300 | 0.0375 | +0.23 |
| CVaR@25% / hard-min / softmin unshrunk | `44_apo` | 0.6075 | 0.0600 | **−0.58 … −0.62** |

Знаки идентичны двум пулам: 6/6 min-based отрицательны, 12/12 averaged /
group-free неотрицательны. На разнообразном пуле даже лучшее правило оставляет
regret 0.0225; пять из девяти правил сходятся на `44_apo` — промпт у дна пула
(0.6075 при pool best 0.6675).

Shrinkage помогает ранжированию (ρ +0.08 → +0.28 на S9, +0.26 → +0.58 на R15)
и выводит soft-min из антикоррелированного кластера, но на S9 всё равно берёт
`44_apo` с полным regret 0.0600. «Shrinkage лучше hard-min» — да. «Shrinkage
решает отбор» — нет.

### F8. Три ручки формулы — одна ручка

Сетка CVaR depth k × softmin τ × shrink w. Spearman vs test CVaR@25%.
Скрипт: `scripts/e5_selection_statistic_ablation.py`
(`results/E5_selection_control/selection_statistic_ablation.json`).

Фрагмент (R15 / S9):

| statistic | w=0 | w=40 | w=400 |
|-----------|----:|-----:|------:|
| CVaR k=1 (hard-min) | −0.57 / −0.62 | −0.51 / −0.54 | +0.48 / +0.02 |
| CVaR k=8 (= mean) | +0.71 / +0.46 | +0.71 / +0.48 | +0.73 / +0.47 |
| softmin τ=0.1 shipped | +0.26 / +0.08 | **+0.58 / +0.28** | +0.73 / +0.44 |
| worst-class control | **+0.71 / +0.68** | | |

Монотонный рост к среднему. Внутреннего оптимума нет: если бы групповая
структура несла сигнал при этом n, лучшая статистика сидела бы между hard-min
и mean. Она не сидит. Оптимальный объём worst-group фокуса в dev-правиле при
*равномерной* аллокации = **ноль**.

Group-free worst-class бьёт все групповые статистики по mean regret
(0.0117 vs 0.0200).

> F9 (RQ6) переворачивает пессимистичное чтение F8: это утверждение про
> **аллокацию**, не про групповую структуру.

### Каузальные иллюстрации, что отбор важнее генератора

**E5v2 (M33).** Тот же мутатор, смена selector на D_dev: test worst-GBA
0.615 → 0.645 (+3.0 pp). E5v1 уже находил C2 heir +4.0 pp, но full val veto
оставил seed. Attribution: `E5V2_WHAT_MOVED_EVOLUTION.md`. Канвас
`e5-v2-run-comparison.canvas.tsx`.

**E5v3 (M40/M41).** Тот же мутатор, ranking по length-penalized fitness:
shipped = seed, test 0.620. Near-miss OE поднимал raw softmin, штраф длины
убивал heir до D_dev. `E5V3_SELECTION_DEBT.md`.

Это абляция протокола отбора при фиксированном генераторе — в instrument-рамке
самое чистое свидетельство, что отбор доминирует над поиском.

### Amazon E6 — частичная репликация

Spearman(dev rule → test cvar25), harshness pool 15 кандидатов:

| rule | ρ |
|------|--:|
| hard_min | **+0.40** |
| cvar25 | +0.26 |
| worst_class | +0.09 |
| mean_macro | −0.01 |
| R_global | **−0.16** |

Min-based **не** антикоррелирует. Плохой селектор — глобальная точность.
Большинство d_dev правил берут `lenient_max` → test 0.431 при oracle
`deflate_positive` 0.458 (regret ≈ 0.027).

## Вывод

При равномерных 50+50 на группу D_dev не может ранжировать промпты по
worst-group. Правила, которые на этом настаивают, систематически выбирают
over-flagger. Это воспроизводится на пуле, к нашему методу отношения не имеющем.

## Чего не хватает

1. Второй независимый draw валидации (все репликации делят один split).
2. se Spearman при n=12/26 велик (≈0.30/0.20) — claim это **знак** по 18
   комбинациям, не отдельный коэффициент.
3. Один scorer. E6 уже показывает, что знак патологии зависит от датасета.
