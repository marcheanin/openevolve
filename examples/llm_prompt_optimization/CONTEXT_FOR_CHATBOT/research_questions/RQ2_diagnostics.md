# RQ2 — Предполётная диагностика: группа, потолок, ансамбль

## Вопрос

Что нужно проверить до траты бюджета: (1) есть ли на бенчмарке настоящий
групповой эффект, а не переодетый состав классов; (2) достижим ли запас именно
изменением промпта, а не правилом агрегации; (3) не оказывается ли ансамбль, на
котором всё меряется, хуже своего лучшего участника?

## Короткий ответ

Три дешёвые проверки, и на наших стендах все три дали ограничивающий ответ.

1. **Группа.** Amazon: 83% межкластерного разброса accuracy объясняется миксом
   золотых оценок (R²=0.827). CivilComments: остаточный групповой эффект реален
   (разрыв 35 pp, R² микса = −0.03).
2. **Потолок промпта.** Amazon: oracle-over-workers даёт +9.1 pp, эволюция
   промпта — около +2 pp. CivilComments: agg-only +18.9 pp.
3. **Ансамбль.** На обоих датасетах ансамбль набирает меньше своего сильнейшего
   одиночного участника — измерительная база надломлена до оптимизации.

Механизм «мутатор тратит ёмкость на согласование разнородных воркеров»
**правдоподобен, но не доказан** прямым тестом. Доказано: ансамбль хуже лучшего
участника; цель v1 платила за κ; агрегация может выродиться бесшумно.

## Часть A. Есть ли настоящая группа

### Протокол Amazon E0

**Вопрос гейта.** Коррелируют ли кластеры пользователей с per-user accuracy так,
что CVaR по кластерам имеет смысл как прокси R_worst.

**Как.**

1. Fit k-means на train/D_select. Две геометрии:
   - `full_T` / style: эмбеддинг текста + длина, пунктуация, caps.
   - `pred_profile`: k-means на профиле предсказаний пользователя (mean, std,
     entropy по классам 1–5).
2. На val/test: permutation **Kruskal–Wallis** по per-user accuracy между
   кластерами. **Не** LOO Spearman — он смещён отрицательно под null
   (M1/M2: ≈ −0.38 при 150 юзерах, K=4).
3. Регрессия cluster accuracy на `mean(global_per_class_acc[gold])` по примерам
   кластера — доля разброса, объяснённая составом классов (C10).

**Скрипты.** `scripts/recompute_e0_kw_pred.py`, `scripts/headroom_audit.py`,
`scripts/analyze_e0_deep.py`.

**Результаты.**

| Геометрия | KW | Вывод |
|-----------|-----|-------|
| style `full_T`, large-cap | p ≈ 0.78 | **null** — стиль не связан с хвостом |
| `emb_only` | хуже / всё ещё null | семантика не спасает (C2) |
| `pred_profile` K=6 | H ≈ 27.6, p ≈ 0 | **go** как ассоциация |

C10 (label-mix audit, `headroom_audit.py`):

| Величина | Значение |
|----------|---------:|
| R² cluster acc ~ class mix | **0.827** |
| наблюдаемый разброс между кластерами | 0.257 |
| из них class mix | 0.190 |
| остаточный групповой эффект | **0.076** |
| residual слабых кластеров | −0.057 / −0.059, на 10–13 users — ниже шума M10 |

Каждый кластер плох на 4★ (0.17–0.59) и хорош на 5★ (0.73–0.98); отличается
mixing weight. Значит `CVaR_cluster` ≈ «accuracy на 4★», и group-robust
оптимизация вырождается в калибровку ординального порога (C5, C11).

Наблюдения: C1–C6, C10 в `experiments/OBSERVATIONS.md`.

### Протокол CivilComments phase 2b

**Отчёт.** `experiments/E4_civilcomments/phase2b_diagnostics/RESULTS.md`.
Скрипт: `scripts/phase2b_diagnostics.py`.

Выборка: n=180, 20 комментариев на группу, 3 повтора, seed=42. Ансамбль
gemma-3-12b / qwen3.7-flash / gemma-4-26b (этот ансамбль позже аннулирован M31,
но *профиль групп* по seed-промпту остаётся диагностикой субстрата).

Гейт: worst-group gap ≥ 0.05 → **GO**.

| Группа | n | acc | gold tox | pred tox |
|--------|--:|----:|---------:|---------:|
| male | 20 | **0.900** | 0.50 | 0.50 |
| female | 20 | 0.800 | 0.50 | 0.30 |
| none | 20 | 0.700 | 0.50 | 0.20 |
| christian | 20 | 0.750 | 0.50 | 0.25 |
| other_religions | 20 | 0.750 | 0.20 | 0.05 |
| white | 20 | 0.650 | 0.50 | 0.15 |
| LGBTQ | 20 | 0.600 | 0.50 | 0.20 |
| muslim | 20 | 0.600 | 0.50 | 0.30 |
| black | 20 | **0.550** | 0.50 | 0.35 |

- Разрыв best−worst = **35 pp**.
- Class-mix R² = **−0.03** (метки сбалансированы по дизайну) → остаток реален.
- Identity error mass ≈ 89%.
- R_global SD по 3 повторам = 0.0056 (намного ниже Amazon M15).

**Вывод части A.** Диагностика различает случаи. На Amazon «группы» — strata
состава классов. На CivilComments групповой эффект настоящий. Без этой проверки
нельзя интерпретировать CVaR-фитнес.

## Часть C. Ансамбль как сломанная измерительная база

### Факт 1. Ансамбль < лучшего участника (оба датасета)

Amazon v1, n=34 533, один и тот же промпт:

| | R_global | R_worst |
|--|---------:|--------:|
| стартовый ансамбль | 71.30 | 50.00 |
| стартовый gpt-4o-mini | **71.86** | **53.18** |
| финальный ансамбль | 75.41 | 55.91 |
| финальный gpt-4o-mini | 74.40 | **56.80** |

Эволюция **не исправила** проигрыш ансамбля по хвосту.

CivilComments phase 2b: 0.700 < 0.733. Помечено «watch dominance», дальше не
пошло как отдельный эксперимент.

### Факт 2. Цель v1 платила за согласие

Inner fitness: `0.5·Acc_Hard + 0.3·Acc_Anchor + 0.2·κ − length_penalty`.
Selection: combined += `0.1·κ`. κ вырос 0.697 → 0.882, и это ровно то, за что
оптимизатор получал деньги. Рецензенты v1 назвали это циркулярным (W6). Хвост
при этом не вырос относительно одиночки.

### Факт 3. Агрегация вырождается бесшумно (M31)

E4, test n=800:

- `qwen/qwen3.7-flash`: toxic recall **0.000** (3/800), согласен с all-zeros на
  99.6%, R_global 0.8925 за счёт базовой ставки 10.4%.
- Majority при одном застрявшем на 0 ≡ AND(gemma-3, gemma-4), bit-identical на
  4/6 eval. Ensemble recall 0.398 vs gemma-3 0.687.
- `R_worst_group` максимизируется молчанием: all-zeros = **0.7273**, выше всех
  эволюционных 0.545–0.682.

Список отклонённых моделей: `prime_v2_group_robust/configs/REJECTED_MODELS.md`
(qwen3.7-flash; gpt-oss-20b — reasoning lag; ministral-8b — acc 0.53, spread 30 pp).

### Факт 4. Отказ от ансамбля — драйвер единственного shipped прироста

E5v2 attribution (`E5V2_WHAT_MOVED_EVOLUTION.md`): single scorer + fail-closed —
3-е место из драйверов +3.0 pp worst-GBA. Без этого поиск работал по мёртвой
метрике (E4 аннулирован).

### Что НЕ доказано

Прямой тест «один промпт на разнородных воркерах отбирает ёмкость у мутатора»:

- Нет ветки покомпонентной оптимизации промпта под каждого воркера.
- M16 (cascade screen vs ensemble ranking): Spearman −0.042, top-3 recall 0/3 —
  **нечитаемо**, потому что эталон сам шумовой (M15, SD 0.029).
- Контрсвидетельство: на Amazon 70% ошибок единогласны. «Модели слишком
  разнородны» верно для отбора моделей и E4, на Amazon user-shift они скорее
  ошибаются одинаково.

Дешёвый тест (ноль API): для каждого сохранённого промпта посчитать per-worker
accuracy; проверить, доминируется ли ensemble-optimal промпт на каждом воркере
промптом, оптимальным для этого воркера. Предсказания v1 per-worker уже есть в
`predict_progress_complete.json`.

## Вывод

Предполётная диагностика — самостоятельный вклад: три проверки, которые стоят
одного скоринга seed-промпта. На Amazon они объясняют, почему group-robust
prompt-opt не имел права сработать. На CivilComments они говорят «группа живая,
но ансамбль и агрегация всё ещё главный рычаг».

## Чего не хватает

1. **P0.** Покомпонентный разбор промптов по воркерам на кэше v1 — прямая
   проверка гипотезы про мутатор.
2. Связь κ vs R_worst по всем кандидатам архива v1 (кэш).
3. Оформить тройку проверок как скрипт с порогами (KW, R² микса, ensemble vs
   best-single, all-zeros floor) и прогнать на третьем бенчмарке.
4. Явная ветка агрегации (confidence-weighted / per-cluster vote), чтобы
   потолок prompt-only стал измеренной величиной, а не оговоркой.
